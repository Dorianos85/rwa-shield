Executable Collateral Value · tokenized stocks · Solana

Oracle price is not cash.

RWA Shield computes Executable Collateral Value (ECV): the USDC a lending venue can actually recover from a tokenized-stock collateral position under stress, instead of the oracle mark.

The problem

Lending against tokenized stocks prices collateral at a mark, not at an exit.

The token trades when the stock does not

Tokenized stocks trade around the clock, while the underlying market is closed on nights, weekends and holidays. A reference price can be hours old when a liquidation actually has to happen.

On-chain books are thin

A forced sale goes through DEX liquidity. For a large position, price impact means the USDC recovered can be well below the oracle value of the collateral.

Fixed LTV sees neither

A fixed loan-to-value ratio on the oracle price lends the same amount in a calm session and in a thin weekend book. The gap between mark and exit becomes bad debt for the pool.

The approach

ECV: value the exit, then lend against it.

ECV = P_oracle × q × D(q) × S(q) × M(t) × V(σ)   ·   B = breaker (gates new credit)

D = routable depth for this size, S = slippage / price impact, M = market-session buffer, V = volatility buffer. Each term is a factor in (0, 1]. The breaker gates new borrowing only; it does not mark existing collateral to zero. Health factor is measured against executable value, so healthy positions are not liquidated just because the market closed.

Five outputs a venue can consume

OutputMeaning
max_borrowMaximum new USDC borrow against this position (0 when the breaker is on).
collateral_capCap on how much of this collateral the venue should accept.
liquidation_routeThe execution route the value is based on (e.g. the quoted DEX route).
risk_premiumRate premium that grows as slippage, session and volatility risk grow.
borrow_disabledBreaker: stale price, depth below floor or extreme impact. New credit stops; existing positions keep their value.

ECV engine

Backtest · synthetic · in-sample

Same loan book, two risk models.

Synthetic, in-sample. 110 days of generated hourly prices (2,640 points) with weekend gaps, not historical market data. The parameters were fitted on the same series they are tested on. This shows how the mechanism behaves, not how it would have performed in a real market.

ScenarioBad debt · fixed 70% LTVBad debt · ECVECV credit vs fixed LTV
Calm base market$0$099.6%
Tail: −22% weekend gap + thin book$3,982,378$00% (369 loans refused)
Liquidity crunch (−70% depth)$297,220$00%

Reproduce: npm run calibrate (writes data/params.fitted.json, also committed) then npm run backtest. With the unfitted default parameters (PARAMS_MODE=priors npm run backtest) the tail scenario is $5,336,023 vs $0. ECV avoids the loss by refusing new credit under stress; that trade-off is the point, and it is visible in the last column.
